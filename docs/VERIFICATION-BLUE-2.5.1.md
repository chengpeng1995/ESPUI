# Blue 2.5.1 UI 与熄屏验证

日期：2026-10-10。工程：`/Users/chengpeng/Desktop/work/ESPUI`。设备：Waveshare ESP32-S3-Touch-AMOLED-1.75，466×466，ESP32-S3 revision 0.2，16 MB Flash、8 MB PSRAM。当前测试串口 `/dev/cu.usbmodem101`。

Blue 2.5.1 已编译并刷入设备，没有擦除 NVS。用户现场确认：**可以触摸唤醒，随后自动熄屏保持黑屏**。本轮保留原工程，代码写在当前 ESPUI 工程。历史 Blue 2.4 电源测试单独保存在 [VERIFICATION-BLUE-2.4.md](docs/VERIFICATION-BLUE-2.4.md)，不将历史结果计为本版新测试。

## 本轮行为

- 首页、应用入口、最近任务使用纯黑背景，删除首页壁纸和进行中任务卡。首页只保留时间、日期和应用入口；时间 64 px、y=162，日期 22 px、y=248，入口 252×56、y=344。计时与闹钟服务继续在后台运行。
- 减少轮播每帧的重复文字和颜色更新，使用已有不同尺寸图标避免逐帧软件缩放。显示刷新请求间隔为 16 ms，触摸读取请求间隔为 8 ms；这两个配置值不等于实际刷新率或触摸采样率。
- 顶部下拉在拖动期间显示快捷面板预览，反向拖动跟随手指。未达提交阈值时 160 ms 回收，提交后从当前高度续接 200 ms 动画。拖动不反复截图或实时计算模糊；提交覆盖层时生成一次背景。关闭返回来源页面，草稿保留；减少动态效果时取消释放动画。
- 修复触摸报告读取后未确认的问题。正常操作与待机验证统一发送 CST9217 读取 ACK（D0 00 AB），空报告、无有效触点或 ACK 失败不恢复屏幕。IRQ 使用当前电平的相反电平唤醒，首次中断屏蔽重复触发。

ACK 依据本地 SensorLib 及其 [上游 TouchDrvCST92xx 实现](https://github.com/lewisxhe/SensorLib/blob/master/src/touch/TouchDrvCST92xx.cpp)核对。旧驱动缺少 ACK 是源码事实；“未确认的有效触摸被再次读取”是修复时的因果推断。最终设备行为另以串口记录和用户反馈确认。

## 熄屏与真实触摸

### 最终 Blue 2.5.1

[自动熄屏与空触摸通知测试](logs/blue-2.5/idle-2.5.1/idle-regression.json)通过：沿用设备 15 秒自动熄屏，在真实电源管理任务与 CST9217 读取路径注入 100 次触摸唤醒通知，100 次均被判为无有效触点而拒绝。36.293 秒观察区间没有恢复屏幕；显示帧、TE 中断、IMU 采样增量均为 0。**这是故障注入，不能称为 100 次真人触摸验证。**

[90 秒只读现场监测](logs/blue-2.5/physical-touch-monitor.log)没有发送唤醒、修改设置或启动测试计时。第一次有效触摸为 (256,229)，恢复流程记录 175 ms、失败 0；约 15 秒后自动进入待机，随后至少 13.993 秒的状态采样保持待机，frame/TE/IMU 增量均为 0。用户对这一次完整流程明确确认“可以唤醒，熄屏后保持黑屏”。之后用户继续操作应用入口、快捷面板和计时器，记录到第二次触摸恢复 174 ms，不能将这些操作误算为自行亮屏。

监测末尾触摸累计 461 次读取、357 次 ACK、ACK 错误 0；读取包含无触点轮询，不与 ACK 数量一一对应。[监测摘要](logs/blue-2.5/physical-touch-monitor.json)保留两次有效触摸报告和恢复记录。ACK 计数不代表真人熄屏/唤醒次数。

175 ms 是设备记录的恢复流程耗时，满足该样本的流程目标；没有光学仪器测量触摸至可见画面的完整延迟。真人明确确认的完整自动熄屏循环为 1 次，尚未完成 100 次真人循环。

ACK 修复前，同一 UI 和电源交接版本完成 [10 次 USB 指令休眠/恢复及一分钟计时跨休眠](logs/blue-2.5/power-retry/device-regression.json)：恢复 167–168 ms，P95 168 ms，失败 0，只读查询重试 0，各次待机 frame/TE/IMU 增量均为 0。计时到点唤醒未保存的日期表单，停止提醒后恢复原编辑页。测试日期没有写入 RTC，测试计时已清理。

首次计时回归与邀请现场操作的时间重叠，受到交互打断；原日志保留在 `logs/blue-2.5/power/`，不计为有效的独立计时验证。随后重试结果单独保存在 `power-retry/`。这些结果标注为 2.5.0，不冒充最终 2.5.1 重测。

USB 主机连接期间保留保护锁，浅睡眠累计为 0 是预期行为。熄屏暂停计算的结果不等于 USB 下进入 Light-sleep，更不代表电池侧功耗。
